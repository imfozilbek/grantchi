# Архитектура Grantchi на бесплатном тарифе

План до первой строки кода. Цель — уложиться в бесплатный тариф Cloudflare с запасом.

## Бюджет

Лимиты Cloudflare общие на весь аккаунт, их делят 5 проектов: Rida, Zumda, ilk•ish, Uyim, Grantchi. Бюджет Grantchi при 1000 активных людей в день:

| Ресурс | Бюджет Grantchi |
| --- | --- |
| Запросы к Worker / Functions | до 5000 в сутки |
| D1, чтение | до 1 млн строк в сутки |
| R2 | до 1 ГБ |
| Cron | ровно 1 |

Лимиты на один вызов Worker: 10 мс CPU, 50 внешних запросов, 50 запросов к D1.

5000 запросов на 1000 человек — это 5 запросов на человека в день. Поэтому всё, что можно отдать статикой, отдаём статикой: запросы к статическим файлам Pages не тратят бюджет Worker.

## Схема

```
GitHub Actions (по расписанию)
  ├─ берёт список источников, у которых подошёл next_check_at
  ├─ скачивает RSS / API / HTML / t.me/s, разбирает
  ├─ AI-пул: перевод на узбекский, поля карточки, чек-лист
  └─ POST черновиков пачками в grantchi.uz/api/internal/* (секрет)
                    │
Cloudflare (один проект Pages + Functions, адрес grantchi.uz)
  ├─ /            Mini App (статика)
  ├─ /catalog/*.json  открытый каталог для гостей (статика, пересобирается при публикации)
  ├─ /api/*       API Mini App и webhook бота
  ├─ /admin       модерация черновиков, за Cloudflare Access
  ├─ D1           данные
  ├─ R2           закрытые файлы
  └─ 1 cron       напоминания и служебные задачи
```

## Риски и решения

### 1. Несколько cron
План требовал 3–4 расписания (сбор, напоминания, проверка свежести, еженедельная проверка фидов).
**Решение:** в Cloudflare ровно 1 cron (раз в 10 минут). Внутри `scheduled()` задача выбирается по времени: каждые 10 минут — напоминания, раз в сутки — пометка просроченных карточек. Сбор источников, проверка свежести и проверка фидов уходят в GitHub Actions — у них своё расписание, и они не тратят лимиты Cloudflare.
Репозиторий публичный, поэтому минуты Actions бесплатны. Учесть: GitHub отключает расписание в публичном репозитории после 60 дней без активности.

### 2. 97 источников не влезают в 50 внешних запросов
**Решение:** источники обходит GitHub Actions, где лимита на 50 запросов нет. В D1 таблица `sources` с полем `next_check_at`: Actions запрашивает список источников, у которых срок подошёл, обходит их и сообщает новый `next_check_at`. Частота у каждого своя: ежедневные агрегаторы — несколько раз в день, официальные программы — раз в неделю. Cloudflare Queues не нужны.

### 3. Разбор HTML и RSS дольше 10 мс CPU
**Решение:** весь разбор — в GitHub Actions. Worker получает уже готовые поля карточки и только пишет их в D1. Если когда-то понадобится разбор в Worker — только потоковый `HTMLRewriter`, без DOM-парсеров.

### 4. Напоминания: одно сообщение — один внешний запрос
**Решение:** таблица `reminders_due` (`user_id`, `opportunity_id`, `send_at`, `sent_at`) с индексом по (`sent_at`, `send_at`). Cron каждые 10 минут берёт до 40 записей с подошедшим сроком, отправляет и отмечает `sent_at`. 40 × 144 запуска = до 5760 сообщений в сутки. Курсор — по `send_at`, не по смещению.

### 5. Каталог с фильтрами
**Решение:**
- Гости и бесплатный слой: открытый каталог — статический JSON (`/catalog/*.json`), который пересобирается и выкладывается деплоем при публикации карточек. Это ноль запросов к Worker и D1. Деплой не чаще раза в сутки (лимит Pages — 500 деплоев в месяц).
- Подписчики: API с составными индексами под каждый фильтр (например `(status, level, deadline)`, `(status, country, deadline)`), пагинация курсором по (`deadline`, `id`), без `OFFSET` и без `COUNT(*)` на каждой странице.

### 6. API и Mini App на разных адресах
**Решение:** API на том же адресе, что Mini App: `grantchi.uz/api/*`. CORS не нужен.

### 7. Mini App и админка
**Решение:** один проект Pages. Админка на `/admin` за Cloudflare Access. Деплой только из CI (GitHub Actions), не вручную.

### 8. Учёт квот AI
**Решение:** таблица `ai_quota` — одна строка на (провайдер, день), счётчики обновляются одним upsert. Не строка на каждый вызов. Cloudflare Workers AI — последним в очереди провайдеров: его бесплатная квота общая на 5 проектов.

### 9. Эссе и личные файлы
Проверка эссе отложена. Когда появится: файлы в закрытом бакете R2 (без публичного доступа и r2.dev), отдаются только через Worker после проверки прав, правило жизненного цикла удаляет их через заданный срок.
